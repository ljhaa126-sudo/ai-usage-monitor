# v1.6.5 修改说明（基于 v1.6.4）

## 1. 点任务提醒 → 切到「任务所在的软件」（以前 macOS 总是跳终端）

**原因**：旧逻辑按固定优先级找正在运行的软件（Claude 只列了终端 / 编辑器），只要终端开着就跳终端，不管任务实际跑在哪。

**现在的查找顺序**（`core/foreground.js` → `WindowActivator.activateEvent(ev)`）：

1. **进程树**（最准）：用系统自带的 `ps` / `lsof`，找到工作目录 = 会话目录（`ev.cwd`）的 claude / codex 进程，
   顺着父进程找到它所在的 `.app`（取最外层，VS Code 的 Helper 归到 Visual Studio Code.app）。不需要任何授权。
2. **发消息时所在的软件**（`ev.hostApp`）：`TaskWatcher` 在看到你发出新消息时记下当时的前台 App（排除本程序自己）。
3. **会话来源**（`ev.host`）：Claude Code 日志的 `entrypoint`（cli / claude-desktop / claude-vscode）、
   Codex `session_meta` 的 `originator`，归为 desktop / ide / cli，再找对应软件。
4. **旧规则**（`ACTIVATE` 列表，已把 Claude 桌面版加到最前）。

切换动作抽成了 `macActivate(app)`：`open -b bundleId` → 前台没变再 `osascript … activate`。日志里会写「依据：…」，方便排查。
Windows：按 `hostApp` → 来源 → 旧列表的顺序找窗口。

改动的文件：`core/tasks.js`（事件里新增 `cwd` / `host` / `hostApp`，导出 `hostKind`）、`core/foreground.js`、
`main.js`（`openTask` 调 `activateEvent`；`TaskWatcher` 传入 `front`）。

**限制**：能切到正确的软件并带到最前，但不能精确到终端里的某个标签页 / 分屏；tmux / screen 里跑的会话找不到所属 App，会退回第 2–4 步。

## 2. Codex（GPT）HTTP 403「服务器返回了网页」

**原因**：chatgpt.com 前面有 Cloudflare。旧版用 Chromium 网络栈（浏览器 TLS 指纹）却带着 `codex_cli_rs` 的 User-Agent，
这种不一致的组合会被判成机器人，返回 403 验证网页。你本机能登录 GPT 不代表这个请求能过。

**现在**（`core/providers.js` → `codexReq`，`core/http.js` → `nodeProxiedTransport`）：

- 依次尝试三种方式，记住成功的那个：
  - `node-cli`：Node 的 TLS + Codex CLI 请求头，与 Codex CLI 本身一致；自动走系统代理，支持 HTTP CONNECT / SOCKS5。
  - `web`：Chromium + 完整浏览器请求头 + 「登录网页版」窗口的 Cookie（含 cf_clearance）。
  - `net-cli`：旧做法，作为兜底。
- 三种都被拦：15 分钟内不再撞墙，直接用本地 Codex 会话日志（`~/.codex/sessions` 里的 `rate_limits`），**正常显示、不报错**，
  只在详细面板给一句说明。登录网页版之后会立即解除（`resetCodexBlock`）。
- 没有 `~/.codex/auth.json` 但登录过网页版：用网页会话换访问令牌。
- 设置 → Codex 现在有「登录网页版」按钮（`DEFS.codex.login`）。

## 测试

`node tests/v165.test.js <app 目录>`：共 19 项，覆盖进程树定位（终端 / VS Code / Claude 桌面版 / tmux / Codex 桌面版）、
查找顺序、任务事件字段、Codex 三种方式切换与本地兜底。用的是模拟的 ps / lsof / lsappinfo / 网络输出，未在真实 Mac 上验证。

# v1.6.6 修改说明

## 1. 所有对话都会提醒（新增 `core/chatwatch.js`）

- Claude 网页版 / 桌面版 / 手机的普通聊天、ChatGPT 普通聊天：这些不在本机留日志，改为用「登录网页版」的登录状态，
  定时查看最近 8 个对话。没有对话在进行时 8 秒查一次，有对话在进行时 3 秒查一次。
  最后一条消息是 AI 的回复并且已写完，就发「已回复」提醒。接口有结束标记时直接用，没有时等两次查询内容不变。
  - Claude 接口：`/api/organizations/{org}/chat_conversations`。Claude 的登录可以是「登录网页版」，也可以是手动填写的 sessionKey。
  - ChatGPT 接口：`/backend-api/conversations`、`/backend-api/conversation/{id}`。复用 Codex 的防 Cloudflare 请求方式（`chatgptAuth` / `chatgptReq`）。
  - 防误报：第一轮只记录现状；最后一条消息早于程序启动的（例如改名 / 收藏旧对话）不提醒；同一条回复只提醒一次。
  - 没登录网页版就跳过、不报错；出错退避（15 秒起，最长 5 分钟）；休眠 / 锁屏时暂停。
  - 点击对话提醒的切换顺序：你发消息时在用的软件（Claude 桌面版 / 浏览器）→ Claude / ChatGPT 桌面版 → 浏览器打开对话链接。
- 本地任务（`core/tasks.js` 的 `readHistory`）：程序启动时正在跑（最近 10 分钟有动静、最后状态是进行中）的会话，跑完也提醒；
  正在等你处理的会话，启动后直接提醒。

## 2. 图标脉冲（`main.js` 的 `onTaskEvent`、`renderer/overlay.js`）

- 以前任务完成时你正停在「相关软件」里（对 Claude Code 来说就是任意终端 / 编辑器）就不加脉冲；
  而且切到任意终端 / 编辑器都会清掉脉冲。所以实际上几乎看不到脉冲。
- 现在：完成 / 需要处理一律加脉冲（绿色 = 完成，橙色 = 需要处理）。只在下面三种情况消失：
  1. 鼠标移到图标上；
  2. 点开提醒；
  3. 脉冲出现之后切到这个任务所在的软件（按记录的 `hostApp` 精确匹配，没有记录时才按软件类型）。
- 被「自动隐藏未连接的 AI」隐藏的图标，有脉冲时也会显示出来。
- 提醒卡片的底部提示改为显示具体去向（如「点击切到 Terminal」「点击打开这个对话」）。

测试：`node tests/chat.test.js <app 目录>`（13 项）。
